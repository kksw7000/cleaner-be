# ReservationYearOutOfRangeException 학습 가이드

## 1. 역할·레이어·왜·언제

`ReservationYearOutOfRangeException`은 예약 달력 조회에서 현재 연도 기준 과거 3년~미래 3년 범위를 벗어난 연도를 요청했을 때 사용합니다. 허용 범위는 연도 변경에 맞춰 동적으로 이동합니다.

## 2. 현재 원본 코드

```java
package com.cleaner.be.reservation;

/** 예약 달력에서 현재 연도 기준 허용 범위를 벗어난 연도를 요청했을 때 발생합니다. */
public class ReservationYearOutOfRangeException extends RuntimeException {

	/** 요청한 연도가 벗어난 최소·최대 연도를 응답 메시지에 포함해 올바른 범위를 안내합니다. */
	public ReservationYearOutOfRangeException(int minimumYear, int maximumYear) {
		super("예약 조회 연도는 " + minimumYear + "년부터 " + maximumYear + "년까지 선택할 수 있습니다.");
	}
}
```

## 3. 구성과 문법

- `RuntimeException`을 상속해 예약 조회의 잘못된 입력을 호출 계층으로 전달합니다.
- 생성자는 현재 연도를 기준으로 계산한 최소·최대 연도를 받아 오류 메시지에 포함합니다.
- 예외 자체는 HTTP에 의존하지 않으며 전역 예외 처리기가 HTTP 400 응답으로 변환합니다.

## 4. 발생 조건과 처리

Controller는 `Year.now()`로 현재 연도를 구한 뒤 양쪽 3년을 허용합니다. 이 범위를 벗어난 입력에는 이 예외를 발생시킵니다. 월 범위 검증은 별도로 1~12를 적용합니다.

## 5. 실제 실행 흐름

달력 가용성 요청의 year가 동적 범위 밖인지 검사→예외 발생→전역 예외 처리기가 계산된 범위를 포함한 `message`와 HTTP 400을 반환합니다. 허용 연도와 월은 기존 월별 가용성 서비스 흐름으로 전달됩니다.

## 6. 관계: 확인된 사실과 추론

- **코드로 확인됨:** 허용 범위는 요청 시점 현재 연도의 전후 3년입니다.
- **코드로 확인됨:** 전역 예외 처리기가 이 예외를 400으로 매핑하고 예외 메시지를 응답합니다.

## 7. 이 파일에만 적용되는 개념

현재 시각에 의존하는 범위는 고정 상수 대신 요청 시점에 계산해야 매년 코드 변경 없이 정책이 유지됩니다.

## 8. 예시

현재 연도가 2026년이면 2023~2029년은 허용되고, 2022년과 2030년은 거부됩니다. 다음 해에는 허용 범위도 함께 한 해 이동합니다.

## 9. 요약

현재 연도 기준 ±3년 정책의 위반을 명시적으로 표현하고, 클라이언트에 유효한 연도 범위를 안내하는 예외입니다.
